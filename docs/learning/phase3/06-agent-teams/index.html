Agent Teams — 複数セッションの並列協調

出典: Orchestrate teams of Claude Code sessions（閲覧日 2026-06-12）
このノートは公式ドキュメントの「agent-teams」を起点に、Claudeが自動生成した教材です。

概要

Agent teams は複数の Claude Code インスタンスを協調して動かす仕組み。1 つのセッションがチームリードとして機能し、チームメイトは独立して作業しながら互いに直接メッセージを送り合える。

注意: 実験的機能でデフォルト無効。CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 で有効化する。Claude Code v2.1.32 以降が必要。

公式 docs に沿った解説

サブエージェントとの比較

SubagentsAgent teams
通信親エージェントにのみ結果を返すチームメイト同士が直接メッセージ
協調親が全ての仕事を管理共有タスクリストで自律調整
トークンコスト低（サマリーとして返す）高（各メンバーが独立した Claude インスタンス）
最適な用途結果だけが重要な集中タスク議論・協調が必要な複雑な作業

既知の制限事項

  • /resume と /rewind は in-process チームメイトを復元しない
  • タスクステータスのラグが起きることがある（タスクが stuck に見える場合は手動確認）
  • シャットダウンが遅い場合がある（現在のリクエストを完了するまで待つ）
  • 一度に 1 チームのみ管理可能
  • チームメイトは独自のチームやチームメイトをスポーンできない（ネスト不可）
  • Split panes は VS Code 統合ターミナル・Windows Terminal・Ghostty では未対応

重要ポイント

  • Agent teams は実験的機能。CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 で有効化が必要
  • チームメイト同士が直接メッセージを送れる点がサブエージェントとの本質的な違い
  • トークン消費が大幅に増える。並列探索が真に価値を持つ場合（研究・レビュー・新機能）に使う
  • クリーンアップは必ずリードから実行する
  • 3〜5 人のチームサイズ、チームメイト 1 人あたり 5〜6 タスクが多くのワークフローで最適

並列コードレビューの例

Create an agent team to review PR #142. Spawn three reviewers:
- One focused on security implications
- One checking performance impact
- One validating test coverage
Have them each review and report findings.

like a scientific debate. Update the findings doc with whatever consensus emerges.
