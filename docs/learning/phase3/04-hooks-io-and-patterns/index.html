Hooks I/O・デシジョン制御・高度なパターン

出典: Hooks reference（後半）および Automate actions with hooks（後半）（閲覧日 2026-06-12）
このノートは hooks リファレンスの I/O フォーマット・デシジョン制御・高度なパターン・安全考察を起点に、Claudeが自動生成した教材です。

概要

Hook の「入出力」と「デシジョン制御」は、単なるシェルコマンド実行を超えた高度な制御を可能にする。stdin でイベントデータを受け取り、stdout と終了コードで Claude Code の動作を制御する。JSON 出力でより細かい決定（allow/deny/defer/ask）や追加コンテキストの注入もできる。

公式 docs に沿った解説

共通入力フィールド（stdin に渡される JSON）

フィールド説明
session_id現在のセッション ID
transcript_pathセッション transcript ファイルのパス
cwdイベント発火時の作業ディレクトリ
permission_mode現在のパーミッションモード
hook_event_nameフックを起動したイベント名
agent_idサブエージェントコンテキストの場合、サブエージェント ID
agent_typeサブエージェントコンテキストの場合、エージェントタイプ

Exit Code Output（終了コードによる出力）

終了コード意味
Exit 0成功・異議なし。UserPromptSubmit / SessionStart では stdout のテキストが Claude のコンテキストに追加
Exit 2アクションをブロック。stderr に書いた理由が Claude にフィードバックとして返る
その他非ブロックエラー。アクションは進む
注意: JSON 出力を使う場合は exit 0 にする。exit 2 のときは JSON が無視される。

JSON Output（構造化出力）

PreToolUse の permissionDecision 値

値挙動
"allow"インタラクティブなパーミッションプロンプトをスキップ（deny ルールは引き続き適用）
"deny"ツール呼び出しをキャンセルし、reason を Claude に返す
"ask"ユーザーにパーミッションプロンプトを通常通り表示
"defer"非インタラクティブモード（-p）でプロセスを終了し、Agent SDK が再開できるようにする

デシジョンコントロール サマリー

イベントデシジョンパターン
UserPromptSubmit, Stop 等トップレベル {"decision": "block", "reason": "..."}
PreToolUse, PermissionRequest 等hookSpecificOutput.permissionDecision 等
WorktreeCreateworktreePath を返す
SessionStart, Setup 等stdout テキストが Claude のコンテキストに追加
SessionEnd, Notification 等なし（ブロック不可）

特別な JSON フィールド

// 端末通知
{ "terminalSequence": "]777;notify;Claude Code;done" }

// Claude へのコンテキスト注入
{ "additionalContext": "Branch: feature/auth\nUncommitted: 3 files" }

プロンプトベースフック（type: "prompt"）

{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "prompt",
        "prompt": "Check if all tasks are complete. If not, respond with {\"ok\": false, \"reason\": \"what remains\"}."
      }]
    }]
  }
}

エージェントベースフック（type: "agent"、実験的）

{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "agent",
        "prompt": "Verify that all unit tests pass.",
        "timeout": 120
      }]
    }]
  }
}

セキュリティ考察

  • Hook のスクリプトはシェルで実行されるため、入力に悪意のあるデータが含まれる可能性を考慮すること
  • PreToolUse フックは bypassPermissions モードでも発火する
  • Hook が "allow" を返しても settings の deny ルールは覆せない。Hook はルールを厳しくはできるが緩めることはできない
  • PermissionRequest フックは非インタラクティブモード（-p）では発火しない。自動 CI では PreToolUse を使う

重要ポイント

  • exit 0 + JSON で細かい制御。exit 2 でシンプルなブロック。両方使うと JSON が無視される
  • "allow" は prompt をスキップするが deny ルールは優先される
  • additionalContext で Claude のコンテキストにテキストを注入
  • prompt フック（Haiku）は ok/not-ok の判断のみ。agent フック（50 ターン）は実際にコードを調べられる
  • CLAUDE_ENV_FILE に書き込むと環境変数を Bash コマンドをまたいで永続化できる
  • Stop フックは 8 回連続ブロックでオーバーライドされる。stop_hook_active フラグを確認してループを防ぐ

コード例 / 図

PreToolUse で破壊的コマンドをブロック

#!/bin/bash
INPUT=$(cat)
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command')
if echo "$COMMAND" | grep -q "rm -rf"; then
  echo "Blocked: rm -rf is not allowed" >&2
  exit 2
fi
exit 0

Stop フックの無限ループ防止

#!/bin/bash
INPUT=$(cat)
if [ "$(echo "$INPUT" | jq -r '.stop_hook_active')" = "true" ]; then
  exit 0  # Claude を止める
fi
# ... フックのメインロジック
