Claude Code の拡張機能 — 全体像

出典: Extend Claude Code（閲覧日 2026-06-12）
このノートは公式ドキュメントの「features-overview」を起点に、Claudeが自動生成した教材です。

概要

Claude Code にはファイル操作・検索・実行・Web アクセスの組み込みツールが備わっており、ほとんどのコーディングタスクをカバーする。その上に重ねる「拡張レイヤー」がこのページのテーマ: Claude が知ること・外部サービスとの連携・ワークフローの自動化をカスタマイズする機能群。新規ユーザーは CLAUDE.md から始め、具体的なトリガーが生じたら他の機能を追加していくのが推奨パス。

公式 docs に沿った解説

拡張機能の一覧

各機能はエージェントループの異なる部分に差し込まれる:

機能役割
CLAUDE.md毎セッション Claude が参照する永続コンテキスト
Skills再利用可能なナレッジと呼び出し可能なワークフロー
Code intelligenceLSP 経由でシンボルナビゲーション・型エラーをリアルタイム提供
MCP外部サービス・ツールと Claude を接続
Subagents独立したコンテキストで処理し、サマリーだけを返す
Agent teams共有タスクリストとメッセージングで複数セッションを協調
Hooksライフサイクルイベントでスクリプト / HTTP / プロンプト / サブエージェントを起動
Plugins / Marketplaces上記機能をパッケージ化して配布

Skills が最も柔軟な拡張。/deploy のようにコマンドとして呼び出すか、Claude が自動的に関連 Skill を読み込む。Skill は現在の会話で実行するほか、サブエージェント（context: fork）経由で隔離実行も可能。

機能の選び方

トリガー追加すべき機能
Claude が規約を 2 回間違えたCLAUDE.md に追記
同じプロンプトを毎回貼っているSkill として保存
同じ手順書を 3 回以上コピペしたSkill として整備
ブラウザのデータを毎回コピーしているMCP サーバーで接続
シンボル探索で多くのファイルを読んでいるCode intelligence プラグインを導入
サイドタスクの出力が会話を埋めてしまうSubagent に回す
毎回必ず実行したいことがあるHook を書く
別リポジトリで同じ設定が必要Plugin にまとめる

ポイント: ".env を絶対に編集しない" という命令を CLAUDE.md や Skill に書いても「お願い」に過ぎない。PreToolUse Hook でブロックすれば「強制」になる。

機能がレイヤーする仕組み

  • CLAUDE.md: 全スコープの内容が同時に追加（上書きでなく合算）
  • Skills / Subagents: 同名が複数スコープにある場合、優先度順に 1 つが勝つ（managed > user > project）
  • MCP servers: local > project > user
  • Hooks: 全スコープのフックが該当イベントで発火（マージ）

コンテキストコストの考え方

機能いつロードコスト
CLAUDE.mdセッション開始毎リクエスト
Skillsセッション開始（説明のみ）＋使用時（本文）低
MCP serversセッション開始（ツール名のみ）低
Code intelligenceファイル編集後・オンデマンド低
Subagentsスポーン時（独立コンテキスト）メインセッションと隔離
Hooksトリガー時（外部実行）ゼロ（出力を返す場合は追加）

重要ポイント

  • 全機能を最初から設定する必要はない。具体的なトリガーが生じたら追加していく
  • Skills は最も柔軟。リファレンス型・アクション型の両方をカバーする
  • ルールの「強制力」が必要なら CLAUDE.md ではなく Hook を使う
  • Subagents はコンテキスト隔離が主な目的。Agent teams はチームメイト同士の協調が必要なときに使う
  • Plugin は複数プロジェクトや他者への配布に使うパッケージレイヤー
