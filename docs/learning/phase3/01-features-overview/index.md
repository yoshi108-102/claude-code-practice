# Claude Code の拡張機能 — 全体像

> 出典: [Extend Claude Code](https://code.claude.com/docs/en/features-overview)（閲覧日 2026-06-12）
> このノートは公式ドキュメントの「features-overview」を起点に、Claudeが自動生成した教材です。

## 概要

Claude Code にはファイル操作・検索・実行・Web アクセスの組み込みツールが備わっており、ほとんどのコーディングタスクをカバーする。その上に重ねる「拡張レイヤー」がこのページのテーマ: Claude が知ること・外部サービスとの連携・ワークフローの自動化をカスタマイズする機能群。新規ユーザーは CLAUDE.md から始め、具体的なトリガーが生じたら他の機能を追加していくのが推奨パス。

## 公式 docs に沿った解説

### 拡張機能の一覧

各機能はエージェントループの異なる部分に差し込まれる:

| 機能 | 役割 |
|---|---|
| **CLAUDE.md** | 毎セッション Claude が参照する永続コンテキスト |
| **Skills** | 再利用可能なナレッジと呼び出し可能なワークフロー |
| **Code intelligence** | LSP 経由でシンボルナビゲーション・型エラーをリアルタイム提供 |
| **MCP** | 外部サービス・ツールと Claude を接続 |
| **Subagents** | 独立したコンテキストで処理し、サマリーだけを返す |
| **Agent teams** | 共有タスクリストとメッセージングで複数セッションを協調 |
| **Hooks** | ライフサイクルイベントでスクリプト / HTTP / プロンプト / サブエージェントを起動 |
| **Plugins / Marketplaces** | 上記機能をパッケージ化して配布 |

Skills が最も柔軟な拡張。`/deploy` のようにコマンドとして呼び出すか、Claude が自動的に関連 Skill を読み込む。Skill は現在の会話で実行するほか、サブエージェント（`context: fork`）経由で隔離実行も可能。

### 機能の選び方

| トリガー | 追加すべき機能 |
|---|---|
| Claude が規約を 2 回間違えた | CLAUDE.md に追記 |
| 同じプロンプトを毎回貼っている | Skill として保存 |
| 同じ手順書を 3 回以上コピペした | Skill として整備 |
| ブラウザのデータを毎回コピーしている | MCP サーバーで接続 |
| シンボル探索で多くのファイルを読んでいる | Code intelligence プラグインを導入 |
| サイドタスクの出力が会話を埋めてしまう | Subagent に回す |
| 毎回必ず実行したいことがある | Hook を書く |
| 別リポジトリで同じ設定が必要 | Plugin にまとめる |

### 似た機能の比較

#### Skill vs Subagent

| | Skill | Subagent |
|---|---|---|
| 正体 | 再利用可能な指示・ナレッジ | 独自コンテキストで動く独立ワーカー |
| 主な利点 | 複数コンテキストでコンテンツ共有 | コンテキスト隔離。中間処理は見えない |
| コンテキストへの影響 | メインウィンドウに追加される | 独立したウィンドウを使う |
| 向いている用途 | リファレンス素材・呼び出し型ワークフロー | 多数ファイルを読む・並列作業・専門ワーカー |

Skill に `context: fork` を付けることで Subagent として実行もできる。

#### CLAUDE.md vs Skill

| | CLAUDE.md | Skill |
|---|---|---|
| ロード | 毎セッション自動 | オンデマンド |
| ワークフロー起動 | 不可 | `/名前` で可能 |
| 向いている用途 | "常に X をする" ルール | リファレンス資料・呼び出し型ワークフロー |

CLAUDE.md は 200 行以下に保つのが推奨。長くなったらリファレンス部分を Skill に移す。

#### Subagent vs Agent team

| | Subagent | Agent team |
|---|---|---|
| 通信 | 親エージェントにのみ結果を返す | チームメイト同士が直接メッセージ |
| 協調 | 親が全ての仕事を管理 | 共有タスクリストで自律調整 |
| トークンコスト | 低（結果をサマリーとして返す） | 高（各メンバーが独立した Claude インスタンス） |

Agent teams は現在実験的で、デフォルトは無効。

#### Hook vs Skill

| | Hook | Skill |
|---|---|---|
| 起動 | ライフサイクルイベントで確実に実行 | Claude の判断 or `/名前` で実行 |
| 使いどころ | 毎回同じように動かしたいルール実施 | 推論が必要なワークフロー・リファレンス素材 |

**ポイント**: "`.env` を絶対に編集しない" という命令を CLAUDE.md や Skill に書いても「お願い」に過ぎない。`PreToolUse` Hook でブロックすれば「強制」になる。

### 機能がレイヤーする仕組み

- **CLAUDE.md**: 全スコープの内容が同時に追加（上書きでなく合算）
- **Skills / Subagents**: 同名が複数スコープにある場合、優先度順に 1 つが勝つ（managed > user > project）
- **MCP servers**: local > project > user
- **Hooks**: 全スコープのフックが該当イベントで発火（マージ）

### コンテキストコストの考え方

| 機能 | いつロード | コスト |
|---|---|---|
| CLAUDE.md | セッション開始 | 毎リクエスト |
| Skills | セッション開始（説明のみ）+ 使用時（本文） | 低 |
| MCP servers | セッション開始（ツール名のみ） | 低 |
| Code intelligence | ファイル編集後・オンデマンド | 低 |
| Subagents | スポーン時（独立コンテキスト） | メインセッションと隔離 |
| Hooks | トリガー時（外部実行） | ゼロ（出力を返す場合は追加） |

## 重要ポイント

- 全機能を最初から設定する必要はない。**具体的なトリガーが生じたら追加**していく
- Skills は最も柔軟。リファレンス型・アクション型の両方をカバーする
- ルールの「強制力」が必要なら CLAUDE.md ではなく Hook を使う
- Subagents はコンテキスト隔離が主な目的。Agent teams はチームメイト同士の協調が必要なときに使う
- Plugin は複数プロジェクトや他者への配布に使うパッケージレイヤー
